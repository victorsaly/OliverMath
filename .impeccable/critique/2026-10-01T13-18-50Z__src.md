## Design specificity verdict

Split, and the split is the story: **the robot is designed; the app is a template the robot was pasted into.**

The six Lottie files are genuinely bespoke — per-state layer stacks (`Sound Ring`, `Sound Wave`, `Gear 1/2`, `Left Tear`, `Blush`, `Happy Eye`) and a `Chest Light`/`Antenna Ball` that recolour per emotion (#4ce6ff idle → #33e666 happy → #5980b2 sad). Nobody could drop this asset set into an unrelated app.

Everything around it is interchangeable. `src/theme/variables.css:1-148` is the verbatim Ionic CLI starter file, comment header included, all ten ramps at Ionic defaults. Stats and Achievements are a dark-navy SaaS analytics dashboard (#1a1a2e / #16213e / #0f3460, 10px uppercase micro-labels with 0.5px tracking). There are four unrelated blues in the product: robot #4c99f2, chrome #3880ff, dashboards #3182ce, status chip #0066ff.

Detector: 7 findings / 3 rules / 4 files, exit 2. 5 confirmed, 2 false positives that exposed a worse bug (see P1-4).

## Priority issues

### P0-1 Every robot animation is frozen for the whole game loop
AnimatedBot.vue:156-168 — `shouldAutoPlay()` returns `isPlayMode`; `shouldLoop()` returns false when `!isPlayMode`. isPlayMode goes false at Home.vue:728 and returns only at :1251. vue3-lottie resolves `autoPlay: false` to `pause()` at load, and the v-if chain mounts a fresh instance per state, each paused on frame 0.
Impact: expanding Sound Rings (listening), pulsing Sound Waves (talking) and turning Gears (thinking) are all switched off precisely during the states they were authored for. Frozen listening and frozen talking both show #4cd9ff marks flanking the head — identical colour, identical position. A pre-reading child cannot tell whose turn it is.
Fix: hardcode `:loop="true" :autoPlay="true"`; drive one-shot behaviour off currentAnimationType, not isPlayMode. Collapse the six-way v-if into one `<Vue3Lottie :animationData="animations[currentAnimationType]" :key="currentAnimationType">`.

### P0-2 The mic-open moment is labelled "Thinking..."
Home.vue:886-888 — `listen()` sets `isComputing = true; isListening = false`. isListening only flips true in speechStartDetected (:913), after the child has already spoken.
Impact: at the one moment the app needs the child to speak, it shows grey gears and the word "Thinking...". A child who waits for the robot to finish thinking gets timed out and scored wrong.
Also: `showExpression('surprised', 800)` at :721 runs before isPlayMode goes false, and surprised maps to the happy animation with a star icon in the chip — so the only animation that plays in the whole loop is a celebration for nothing.
Fix: set isListening true / isComputing false before constructing the recogniser. Add a distinct "Your turn!" string. Feed the child's own mic amplitude into the existing audioLevel prop (currently driven by TTS output).

### P0-3 isError is a one-way latch that permanently removes the Play button
Home.vue — assigned true at :708, :813, :819, :936, :1349; never assigned false anywhere (only initialised at :312). Verified by grep. botState returns "broken" whenever true (:377-380) and the footer gates the Play button on `botState !== 'broken'` (:208).
Impact: one denied mic permission, one cold Azure Function, one flaky connection and the app is permanently unplayable — crying robot, no button, a toast that already vanished. broken maps to the same sad animation as a wrong answer, so a system failure reads as the child's failure. A 7-year-old will not refresh a standalone PWA.
Fix: reset isError at the top of askQuestion. Give broken its own animation and copy. Replace the toast with a persistent tappable recovery card. Never hide the Play button; disable it with a visible reason.

### P0-4 Silence is scored, spoken and recorded as a wrong answer
Home.vue:1131-1152 → :1217-1247. Empty result falls into the final-result else branch: consecutiveCorrect = 0, playIncorrectSound(), error haptic, speaks "Not quite, the answer is 56", and writes isCorrect:false to permanent history.
Correction to the design review: silence shows the *confused* face, not tears — :1226 guards it with `if (!isSilent)`. The scoring, sound, haptic, speech and history write all still fire.
Impact: in the real scene — a child on a phone with other people in the room — non-capture is the most likely turn outcome, not an edge case. The app tells the child they were wrong when they never got to answer, breaks the streak, and poisons the stats that drive getRecommendedDifficulty, so it then makes the problems easier because the room was loud.
Fix: branch `isSilent && isFinalResult` away from the wrong-answer path entirely. Own state, "I didn't hear you — say it again!", automatic re-listen.

### P0-5 Zoom locked + 9px type
index.html:10 — `maximum-scale=1.0, user-scalable=no` (verified). 40 of 44 font-size declarations are px, down to 9px: Achievements.vue:356, :362, :387; Stats.vue:438. WCAG 1.4.4. Two independent decisions that together remove every path to larger text.

### P0-6 Hero star count is invisible
Stats.vue:218 — `.star-count { color: #ffffff }` over a #ffd700→#ffed4a gradient. 1.40:1 falling to 1.20:1; large text needs 3:1. The child's star total — the whole reward loop — cannot be read. Fix: #000 gives 14.97:1.

### P0-7 No prefers-reduced-motion anywhere
Verified: zero occurrences in src, against 38 @keyframes and 85 animation declarations. Two infinite loops (Home.vue:1674, Stats.vue:202) and up to 100 individually-animated fixed-position particles in confetti.js:175-189. Home.vue:1687-1689 is an *empty* dark-mode query containing only a comment. Fix needs a real reduce block that stops the pulses and short-circuits confetti — not a blanket 0.01ms kill, which would destroy the correct/wrong feedback the game depends on.

### P1-8 Status chip is invisible in light mode; Play button label fails AA
Home.vue:1482 `--background: #0066ff` never applies — ion-chip is shadow-encapsulated and `:host(.ion-color)` sets `background: rgba(var(--ion-color-base-rgb), 0.08)` directly. Real pairs: white on #eefbf3 / #fffaeb / #eff5ff / #f6f6f7 = 1.04–1.11:1. The app's only written state indicator is blank on any phone not in dark mode. All 12 statusColor branches are therefore dead.
Play button: #ffffff on #3880ff at 18px/600 = 3.68:1 (3.27:1 in dark). 18px/600 is not "large text".

### P1-9 455KB Speech SDK on the critical path
docs/assets/speech-sdk-COlTfjHb.js = 455,101 bytes in a `<link rel="modulepreload">`. Initial JS ≈ 1.49MB uncompressed before a child sees a robot. ### P1-12 Achievement badges are empty coloured circles
Achievements.vue:271-281 sets `font-size: 32px` with no glyph content; the only child is the lock, shown when locked. Unlocking a badge makes its icon disappear. ### P1-13 Two of four routes are unreachable; one is an unmoderated LLM chat
Only one navigation link exists in the whole app (Home.vue:34 → /stats). /assistant is a free-text LLM chat with a textarea, no back button and no age gating, shipping 39,464 bytes and dragging in axios. /bot-preview is a dev tool with a speed slider.

### P1-14 Equation is never shown, only spoken
Home.vue:808 renders the sentence "What is 7 times 8?" at 17.6px. OPERATOR_SYMBOLS exists (gameConfig.js:18-23) and the symbolic form is rendered in the history modal and on Stats — everywhere except where the child is solving it. The correct answer after a miss is also spoken only, never shown as 7 × 8 = 56.

### P2-15 Interim transcripts fire an LLM call each
Home.vue:917-920 — `recognizing` calls validateSpeechRecording per partial hypothesis: a toast + a /api/validateAnswer POST + an isComputing flip each. One spoken "fifty-six" can produce 3-5 toasts, 3-5 round-trips and 3-5 animation reloads.

Also: .action-buttons is gated `v-if="!isPlayMode"`, so mute and history are unreachable from the idle screen and appear only mid-question.

## What's working

1. The Lottie character set is real design work at the right granularity — state encoded in the shape and colour of a character rather than in text, which is exactly the right channel for a pre-reading user. Six files, 200×220 at 30fps, 14-17KB each. 89KB total. This is the opposite of the usual oversized-Lottie problem.
2. The reward layer is genuinely multi-channel and escalates: three melodies by streak tier, particle count scaling with streak, differentiated haptics, and twelve correct phrases / five softened corrections per language. The correction copy never says "wrong" — it says "Close! It's 56".
3. Speech-bubble typography is correctly specified for an early reader: ~34 characters per line at 17.6px/500, line-height 1.4, #2d3748 on near-white at 11.99:1.
4. Clean toolchain — eslint and vue-tsc both exit 0, no TODO/FIXME/HACK anywhere.
5. Absent landmines: zero will-change left at rest, no backdrop-filter, no layout thrashing in JS, restrained shadows, thorough unmount cleanup (Home.vue:1357-1377).
6. Several a11y basics already right: aria-hidden on 12 decorative icons, aria-label on all 9 icon-only buttons, role="alert" on banners, lang on html, no outline:none in live code.
7. Sensible service-worker strategy and Web Audio synthesis instead of shipping sound files.

## Persona red flags

7-year-old early reader: cannot distinguish frozen listening from frozen talking, so talks over the robot or waits through their own turn. Cannot read "Practice Weak Areas" vs "Practice Recent Failures", so sets the mode by accident. Sees the robot celebrate before any question is asked. Cannot find Repeat when they need it. Hits the wrong one of six 28px controls.

Child in a noisy room (the most common scene): silence → confused face → full wrong-answer branch, streak reset, "Not quite, the answer is 56", permanent failure row. A sibling's voice fires repeated recognizing events, each a toast + LLM call + state flip. No "say it again", no cancel. Shouting the right answer during the question captures nothing — listen() is only called from audio.onended.

Parent setting it up: the mic permission dialog fires from mounted() on page load, with no user gesture and nothing explained — on iOS Safari that is where it is most likely refused. If they tap "Don't allow", the app permanently bricks itself with no "open Settings" instruction anywhere. Three seconds later the install banner covers the Play button.

Child with a quiet voice or an unusual accent: validateAnswer returns a confidence field (apiService.js:86) which Home.vue:1112-1114 logs to the console and discards. The one field that could drive "I think you said 56 — is that right?" is already crossing the wire and being thrown away.

## The 3D robot question

cloudai-x/threejs-skills is usable: 10 well-formed skills, with threejs-animation (AnimationMixer, skeletal clips, morph targets) and threejs-loaders (GLTF/Draco) being the relevant two. Its README's install commands point at an unrelated repo (pinkforest/threejs-playground) — a copy-paste bug; clone the real URL.

Ideal donor model exists: three.js ships RobotExpressive.glb, 464KB, CC0 1.0, with clips Idle/Yes/No/ThumbsUp/Wave/Dance/Jump plus three facial morph targets (Angry/Surprised/Sad).

Recommendation: not yet, and possibly not at all. The app already ships 1.49MB of uncompressed JS before first paint; adding ~600KB and a WebGL context on a 7-year-old's phone is the wrong order of operations. More to the point, the current robot is not failing because it is 2D — it is failing because P0-1 freezes it and P0-2 mislabels it. Those are two computed properties and one state assignment. Fix them and the bespoke character work starts doing its job for the first time; then re-evaluate 3D against a clean baseline.

## Recommended order

1. P0 correctness: unfreeze the animations, fix the listening state, reset isError, branch silence out of the wrong-answer path. Small diffs, highest payoff.
2. P0 accessibility: unlock zoom, fix the star count and status chip contrast, add a real reduced-motion block.
3. Slop removal: delete BotFace.vue, the dead index.html/manifest/api layer, the dead CSS and strings.
4. Payload: lazy-load the Speech SDK and Home.
5. Theming: delete the custom dark block, build tokens that belong to this product.
6. Then reconsider 3D.
